# Tomato Novel Submission Preparation

This is a working checklist, not a guarantee or a replacement for current platform rules. Re-check the official author center before each submission because requirements and interface details can change.

## Prepare the Work

1. Confirm the author owns or is authorized to publish all manuscript text and assets. Remove unauthorized adaptations and copied passages.
2. Check author eligibility and verification requirements directly in the official creator interface. Do not put identity, phone, or bank details into chat.
3. Prepare accurate title, category, tags, synopsis, cover brief, opening chapters, and a sustainable update plan.
4. Review content, formatting, chapter boundaries, sensitive themes, and originality. An internal checklist cannot predict or guarantee platform review.
5. Save the exact submitted version and date the preparation checklist.

## Signing and Recommendation Review

1. Verify the current official signing criteria and application path for this author account and work.
2. The author reviews contract terms and handles signatures and personal/payment details themselves.
3. Track each status, platform message, requested revision, and response date as shown in the official dashboard.
4. Check current recommendation/evaluation rules separately. Signing does not guarantee recommendation or traffic.
5. Turn feedback into a revision checklist, retain the prior version, and prepare a response for the author to review and submit.

## Tracker Fields

Record work/version, date, status shown in platform, official feedback, affected chapters, next author action, and resubmission date. Do not automate login, contract acceptance, application submission, or publication. All outcomes are controlled by the platform.

## Cross-Platform Sync

Publishing is opt-in. If the request is for writing, editing, review, or submission preparation only, do not sync or publish anywhere. When the user explicitly requests synchronized publishing, record each named platform, work, chapter range, and timing; format and validate each destination separately; check existing publication state to prevent duplicates; then publish only within the explicitly authorized scope. If a destination requires login, consent, or another live action not clearly authorized, prepare the final package and ask for authorization before that action. Log the publication URL/status and timestamp for each destination.
